AI Chip Architecture（AI芯片架构）

Definition

AI Chip Architecture 是指针对 AI 工作负载（主要是矩阵乘法）进行优化的芯片设计方案。理解芯片架构的核心在于一个贯穿整个技术栈的统一主题：最大化 compute/communication 比率——即在每个时钟周期里，让更多晶体管做实际的计算，而不是在移动数据。

从最底层的逻辑门到最顶层的多芯片互连，这个比率决定了芯片的最终效率。不同架构（GPU、TPU、FPGA、ASIC）的本质差异在于它们对这个比率做了不同的权衡。

The Core Problem: Data Movement Dominates

根据 Reiner Pope（MatX CEO，前 Google TPU 工程师），AI 芯片最根本的效率问题不是计算速度，而是数据搬运成本：

  • 一个典型 CUDA core 中，从寄存器文件读取数据的 mux 电路成本为 O(n×p)（n=寄存器深度，p=位宽）
  • 实际 multiply-accumulate（MAC）电路成本仅为 p×q（q=乘数位宽）
  • 在一个简单的 8 条目寄存器文件 + MAC 单元中：~7/8 的芯片面积花在数据移动上，仅 ~1/8 花在实际计算
  • 这就是 Tensor Core（Volta 代起）和 systolic array 被引入的原因——将更大粒度的计算固化到硬件中，摊薄数据移动开销

这个”隐藏的数据移动成本”是理解所有 AI 芯片架构差异的起点。

Architecture Classification（架构分类）

AI 芯片架构的分类不是平面的——它在两条独立的轴线上做权衡。正确的方式是分两层看：

第一层 FPGA vs ASIC：要不要可编程性？→ 决定效率天花板

第一层：FPGA vs ASIC（可编程性）

最根本的分歧是：你愿意为可编程性牺牲多少效率？

维度FPGAASIC
可重编程✓ 现场可改，负载可频繁更新✗ tape-out 后锁定
效率比 ASIC 差 ~10x（面积×功耗）最高
首个成本~$10K（开发板）~$30M+（tape-out）
单芯片成本高最低
编程难度高（Verilog）最高（Verilog，更复杂的设计规则）
适用场景量小、负载频繁变更、需要确定性延迟量大（>100K units）、负载确定
典型用例Jane Street HFT，微软 Catapult AI 推理NVIDIA GPU, Google TPU, 比特币矿机

FPGA（Field-Programmable Gate Array）

内部结构：由三部分组成——寄存器（存储）、查找表 LUT（可编程门）、mux（可编程连线）。“Muxes all the way down”——每个 LUT 内部实际就是一个 16→1 的 mux（成本 ~32 个门），每个 LUT 的输入又从附近 8 个来源中通过 mux 选择。编程 FPGA = 配置每一个 mux 的控制位。

10x 效率惩罚的来源：一个 4-way AND 在 ASIC 中仅需 ~3 个门，在 FPGA 中需 ~32 个门（通过 LUT 实现）。这个差距是物理性的，不是迭代能解决的。

为什么 HFT 用 FPGA？ 确定性延迟。CPU 的 cache 和分支预测器引入非确定性延迟，FPGA 的时钟周期是严格确定的。但 10x 惩罚意味着它不适合大规模 AI 训练。

ASIC（Application-Specific Integrated Circuit）

核心原理：将逻辑门直接布线在硅片上，没有多余的 mux 开销。首批 $30M+ 的 tape-out 成本换来了每颗芯片的最低制造成本和最高能效。

第二层：GPU 风格 vs TPU 风格（单元粒度）

这一层的核心问题是：你愿意为灵活性牺牲多少密集矩阵效率？ 两者都是 ASIC，但给出了不同的答案。

GPU 风格 — NVIDIA/AMD 架构

维度特征
本质”一堆小 TPU 平铺在芯片上”（Reiner Pope 描述）
核心单元SM（Streaming Multiprocessor），每个含 Tensor Core（小型 systolic array）+ warp scheduler + register file + vector unit
优势灵活性高，覆盖范围广——从训练到推理，从密集矩阵到稀疏计算，从大模型到小模型
劣势控制开销叠加——每个 SM 的 warp scheduler/寄存器文件在大规模矩阵乘时是无谓开销

关键演进：Volta 前，GPU 使用通用 CUDA core（ALU + 寄存器文件，7/8 面积花在数据移动）。Volta 引入 Tensor Core（固定功能 systolic array），将 compute/communication 比率大幅提升。B300+ 开始承认 FP4:FP8 速度比 ~3x（理论值 4x），反映精度缩放效应。

TPU 风格 — Google/Groq 架构

维度特征
本质为矩阵乘法极致优化的 ASIC——放弃灵活性换取效率
核心单元MXU（Matrix Multiply Unit）——大型 systolic array（如 128×128）
优势面积效率最高——大型阵列摊薄寄存器文件和控制开销；scratchpad 提供确定性延迟
劣势灵活性受限——仅 2-3 条数据路径；小矩阵或稀疏工作负载效率大幅下降；编译器要求高

Scratchpad vs Cache：TPU 使用 scratchpad（软件管理内存）而非 GPU 的 cache（硬件管理）。程序员需要明确指令”读/写 scratchpad”和”读/写 HBM”，而非让硬件决定是否 cache hit。这带来确定性延迟但需要更多编译器工作。Groq 也采用此方案。

Key Architectural Trade-offs

1. Compute/Communication Ratio — 贯穿整个技术栈的统一主题

从最底层到最上层，同样的原则反复出现：

层级通信开销计算收益优化手段
精度 (FP4 vs FP8)位宽 × 位宽 → 二次方低位宽 MAC 面积低精度推理
MAC 单元mux 成本 O(n×p)MAC 成本 O(p×q)Systolic array
Systolic array寄存器文件带宽 O(x)计算 O(x×y)大型数组（如 128×128）
芯片间网络带宽总 FLOPS大 batch size
集群AllReduce 通信训练吞吐模型并行策略

2. Precision Scaling（精度缩放效应）

关键公式：一个 p 位 × q 位的乘法器需要 p×q 个 AND 门 + p×q 个 full adder。

这意味着：位宽减半，计算硬件需求减少约 4x（二次方），而非 2x（线性）。这就是低精度推理拥有结构性优势的根本原因。

NVIDIA 的历史实践（FP4:FP8 = 2x）实际上是保守的，因为：

  • 数据移动也有收益：两个 4 位数字可打包进一个 8 位存储 → 有效内存带宽翻倍
  • B300+ 开始转向 3x 比率，向理论 4x 靠近

3. Systolic Array（脉动阵列）

Systolic array 是将 MAC 单元组织成网格，使数据在阵列中”脉动”流动，最大化计算/通信比率的架构模式：

  • 工作原理：权重矩阵静态存储在阵列本地寄存器中；输入向量从一侧流入；结果从另一侧流出
  • 优势：将 O(x×y) 的矩阵乘法通信压缩为 O(x) 的输入/输出带宽
  • 加载策略：权重通过 daisy chain 慢速加载（一次加载，多次使用）
  • 典型规模：Google TPU 早期为 128×128 阵列
  • GPU 实现：Tensor Core = 较小规模的 systolic array（如 4×4×4 或 8×8×8）

4. Cache vs Scratchpad（缓存 vs 软件管理内存）

特性Cache (CPU/GPU)Scratchpad (TPU/Groq)
管理方式硬件自动管理软件（编译器/程序员）明确管理
延迟非确定（取决于 hit/miss）确定
面积效率低（控制逻辑复杂）高（简单内存阵列）
编程难度低（透明）高（手动管理内存层次）
典型设备CPU, GPU (CUDA)TPU, Groq

5. Pipeline Registers and Clock Cycles

时钟周期是芯片全局同步机制：每 ~1ns，所有电路暂停、同步、进入下一操作。

  • Pipeline register insertion：在长逻辑链中插入寄存器可将逻辑分块，允许更高时钟频率——但增加面积开销
  • 权衡：极高时钟频率（如 5+ GHz）意味着大量面积变成 pipeline registers，实际 throughput 反而下降
  • Feedback loop 约束：最难的路径是有反馈回路的计算（如累加器），它设定了芯片的极限时钟频率
  • 类比：如同 batch size——小 batch 低延迟低吞吐，大 batch 高延迟高吞吐

Why It Matters for Investing

  1. 理解芯片公司的真正竞争优势：NVIDIA 的护城河不仅是制程节点（TSMC 也能为 AMD 做），更是 CUDA 生态 + Tensor Core 架构 + NVLink 互连的综合优势。架构决策（systolic array 规模、内存层次、数据路径带宽）直接决定推理/训练效率差异。

  2. FP4 精度革命是结构性趋势：精度降低带来的 ~4x 面积优势是数学上的必然，不依赖工艺进步。这意味着 AI 推理 ASIC 将不断侵蚀 GPU 的推理份额——因为推理对灵活性需求低，可以极致优化精度。B300+ 的 3x FP4:FP8 比率证实这一趋势正在加速。

  3. FPGA 永远无法成为 AI 训练主力：10x 效率差距是物理性的，不是迭代可解决的。但 FPGA 在延迟敏感、频繁变更的特定场景（HFT、网络加速）仍有不可替代的 niche。

  4. 自研 ASIC（TPU/Trainium/Maia）的合理性：Hyper scaler 自研芯片的核心逻辑——当矩阵乘法是压倒性工作负载时，放弃灵活性换取 2-3x 效率提升是数学上合理的选择。Google TPU 同等 Flops 训练成本仅为 GPU 的 20-30% 符合这一理论预测。

  5. Split-table Systolic Array（MatX 的差异化）：如果真实世界推理工作负载既有大型密集矩阵（需大阵列）又有稀疏/不规则计算（需小阵列），可拆分阵列可以在不牺牲效率的前提下覆盖更多场景。这是 MatX 的核心架构论点。

  6. 数据移动瓶颈决定行业结构：7/8 面积花在数据移动 → HBM/内存层次创新（HBM4、near-memory compute、3D stacking）的收益可能大于 MAC 单元创新。这有利于内存厂商（mu、hymx）和先进封装（tsm CoWoS）。

Open Questions

Question

  • Splittable systolic array 在真实推理负载中的收益 vs 控制复杂度——能否同时在大型密集矩阵和小型稀疏计算中都保持高效率？
  • NVIDIA 的 “GPU = 一堆小 TPU” 架构是否会随着 CUDA 生态的优化（如更粗粒度的 Tensor Core、更大的 SM 内阵列）逐步收敛到 TPU 的设计方向？
  • 如果 ~7/8 面积花在数据移动，那么 HBM4 / near-memory compute / 3D stacking 哪一个方向能带来最大的 compute/communication 比率飞跃？
  • 确定性延迟（scratchpad 方案）在 AI 推理中是否真的重要？还是只有在 HFT 等极低延迟场景才有意义？
  • 精度二次方缩放意味着 FP2 推理理论上比 FP4 再快 ~4x——但模型精度能容忍多少？
