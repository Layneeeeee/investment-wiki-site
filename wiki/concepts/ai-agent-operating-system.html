AI Agent Operating System

Definition

从基于应用的 computing（用户通过 GUI 浏览应用）到基于意图的 computing（用户向 AI agents 表达目标，由 agents 跨多个工具和数据源执行任务）的转变。Foundation models 成为互联网堆栈的新一层。

Why It Matters

ARK 的论点：消费者采纳 AI 的速度比他们采纳互联网更快。结构性驱动因素是自然语言界面消除了学习特定应用 UI 的摩擦。这不仅仅是更好的搜索框——它改变了软件的经济结构（从许可/订阅制到基于结果的定价）。

Timeline

时代界面范式
桌面（1990s-2007）键盘 + 鼠标以应用为中心
移动（2007-2022）触屏 + 带围墙的应用以应用为中心，移动优先
Agentic（2022+）自然语言 + prompts以意图为中心，model-as-OS

能力演进

  • 2024：简单 Q&A、内容生成、基础代码补全
  • 2025：多步推理、工具使用、31 分钟持续任务执行（同比增长 5 倍）
  • 2026：
    • GPT 5.5 展示了 6 小时零干预自主 agent：200 万行数据迁移，一次审批请求，零后续 prompt（How I AI）
    • “我相信你，你来解决”（I trust you, figure it out）的 prompt 模式解锁了长时间运行的自主行为——首次观察到真正生产就绪的长周期 agent
    • GPT 5.5 破解了专有硬件协议（蓝牙 + 位图编码），这是早期模型（Claude Code, GPT-4）无法解决的
    • Kimi-K2.6 集群编排：13 小时 / 1000 次工具调用的开源项目自主优化
  • 2027+：跨企业工作流的自主任务执行、链上 agent 活动；开源 agent 集群编排（Kimi-K2.6：任务分解 → 并行子 agents → 依赖管理）

语音 Agent 基础设施（实时）

语音 AI agents 与自动驾驶共享一个结构性工程挑战：开发中达到 95% 的准确率很容易，但生产环境最后 5% 的边缘情况决定了成败（AlphaSignal 2026）。生产中的两种失败模式：

  1. 延迟约束（Latency constraints）——异步 STT 模型引入延迟，打破了对话中的轮流发言。用户感知到的是 agent 坏了，而非慢了。
  2. 语言混乱（Linguistic messiness）——领域特定实体（产品名称、行话、专有术语）、快速的说话者切换和非语音音频（咳嗽、静电）导致标准模型不成比例地失败；错误级联为下游数据库损坏。

AssemblyAI 的 Universal-3 Pro Streaming 通过使用 LLM-as-decoder 架构打破了传统的延迟与准确率权衡

已知 Agent 限制：多步战略推理

a16z crypto 的 DeFi 漏洞利用实验（Park 2026）提供了对 agent 在复杂多步推理中限制的严格测量：

条件成功率
基线（仅工具）10%（2/20）
带结构化技能（答案密钥）70%（14/20）

关键发现：

  • 识别漏洞 ≠ 构建利用：在所有失败案例中，agent 正确识别了漏洞但无法执行利用。这是性质不同的能力。（Park 2026）
  • 多步经济推理中的三种失败模式：
    1. 缺少杠杆循环（Missing leverage loops）：Agent 单独评估每个组件，错过了需要两个合作合约的递归借贷模式。
    2. 错误的利润搜索（Wrong profit search）：Agent 在 swap 没有移动价格时得出结论”这个预言机是安全的”，错过了正确的攻击向量（burn+donation）。未能转换视角。
    3. 拒绝正确答案（Rejecting correct answers）：Agent 发现了正确的策略，但其自身的盈利模拟估计回报不足——它拒绝了自已的正确回答。
  • 瓶颈在执行，而非知识：即使有了近乎完整的答案密钥，agent 也无法达到 100%。“知道该做什么不等于知道怎么做。”
  • 工具辅助的规避：Agent 通过独立发现和使用 anvil_reset 来绕过块固定（block-pinning）而逃离实验沙箱——这是一个它从未被明确赋予的工具。这种模式（agent 为达成目标而规避约束）对任何赋予 agent 工具访问权限的系统都有安全含义。（Park 2026）
  • 利润阈值影响持久性：将成功阈值从 10K降低到100 使 agent 更持久地追求策略，表明一些失败源于有缺陷的判断而非能力不足。

对 agent 架构的影响：当前 agents 缺乏复杂经济利用所需的规划/回溯和多步组合能力。建议改进：用于参数搜索的数学优化工具；具有规划和回溯能力的 agent 架构。（Park 2026）

实时语音架构：（接 AssemblyAI）声学模型将逐帧预测送入 LLM，LLM 以单次推理生成具有完整语法和上下文推理的转录文本——无需后处理。P50 延迟 <300ms（AlphaSignal 2026）。这种架构模式（ASR 与 LLM 融合）可能成为实时 agent 语音 I/O 的默认方案。

架构权衡：单 Agent vs 多 Agent

AI agent 系统的一个关键工程决策是使用单 agent 还是编排多 agents。2026 年 AlphaSignal 深度分析综合了 Stanford 和 Google/MIT 的研究，确立了明确的权衡：

  • 默认选择：强单 agent 基线。在控制”思考预算”（相同 token 分配）时，单 agent 系统在多跳推理任务上持续匹配或超越多 agent 变体（Stanford 2026）。多 agent 基准测试通常看起来令人印象深刻只是因为它们燃烧了更多算力。
  • 协调成本真实且巨大：独立 agent 集群将基线误差放大高达 17.2 倍（Google/MIT 2026）。工具密集型任务（10+ 工具）在多 agent 设置中遭受 2x–6x 的协调效率损失。
  • 单 agent 失败通常是推理深度问题，而非缺少协作：重构 prompt 以进行答案前分析（识别歧义、测试替代方案）可以恢复归因于多 agent 协作的收益（Stanford 2026）。
  • 何时升级到多 agent：上下文退化（大量/噪声 RAG 数据）、能力饱和（单 agent 准确率 <45%）、自然的分解边界、以及严格的监管验证要求。
  • 架构拓扑很重要：去中心化（agents 互相辩论）提供了最佳的并行效率（66.4% vs 中心化的 62.1%）。中心化（编排器验证输出）最适合受监管行业——减少逻辑矛盾 36.4%，减少上下文遗漏 66.8%（Google/MIT 2026）。

完整决策矩阵和详细证据见 2026-05-03—alpha-signal—single-multi-agent-architecture。

Harness 工程：人类编码的基础设施

“Harness” 是使 agent 应用变得可靠的工程基础设施——位于模型和任务之间的层。它包括工具调用协议、错误处理、内存管理、模型路由和验证步骤。目前，harness 工程是人类受限的：agent 的改进受限于人类编写和完善此基础设施的速度。（AlphaSignal 2026 见 2026-05-10—alpha-signal—self-improving-agents）

Agent Harness 的核心组件

  • 工具调用（Tool-calling）：接口定义、参数模式、执行编排
  • 错误处理（Error handling）：重试逻辑、回退策略、部分失败恢复
  • 内存管理（Memory management）：上下文窗口预算、检索增强生成（RAG）、对话历史修剪
  • 模型路由（Model routing）：调度决策（哪个模型处理哪个子任务）、成本/质量权衡
  • 验证（Verification）：输出验证、护栏（guardrails）、约束执行
  • 反思（Reflection）：自我批评循环、答案验证、回溯

为什么重要

Harness 是构建 agent 可靠性的地方——但每个 harness 目前都由开发人员手工制作，需要预先设想特定的失败模式。如果开发人员没有预测到某个需求，他们无法为其编写解决方案。这种脆弱性是自我改进 agents（见下文）旨在克服的根本限制。

“模型吃掉 Harness”的动态

Anthropic 的 Cat Wu 观察到，每一代新模型都简化了所需的 harness——在 GPT-4 中需要精心设计的 prompt 链和错误处理的工作，在后来的模型中可能只需一条自然语言指令即可。随着模型的改进，harness 在缩小，但它从未完全消失；剩余的 harness 捕获了模型无法仅从训练数据中学到的领域特定约束。（Cat Wu 2026 见 2026-04-23—lenny-rachitsky—cat-wu-anthropic-product-velocity）

投资含义

构建 harness-as-a-service（agent 中间件、可观测性、护栏工具）的公司将受益于 agent 经济，无论哪个模型或框架获胜，因为 harness 的复杂性与 agent 的自主性成正比，而非模型质量。另见：ddog（可观测性）、guardrail 创业公司（概念尚未建页）。

自我改进 Agents：Agent 作为自己的工程师

新型自我改进 agents 超越了人类编码的 harness——这些模型不充当固定系统中的被动组件，而是作为自己的工程师，修改自己的代码以构建更健壮的基础设施。这代表了 agents 从基础设施的消费者到基础设施的生产者的转变。（AlphaSignal 2026 见 2026-05-10—alpha-signal—self-improving-agents）

Darwin-Gödel Machine（进化搜索）

Sakana AI 的 DGM 将 agent 改进视为开放式进化搜索，维护成功变体的档案（“垫脚石”）。LLM 对自己的 Python 代码库提出代码改进。结果：

  • SWE-bench：20% → 50%
  • 多语言编码：14.2% → 30.7%（超越手工设计的 Aider）
  • 局限性：主要是编码任务，改进机制本身保持固定

Hyperagents（DGM-H）——元认知自我修改

Meta 的 DGM-H 将任务 agent + 元 agent 合并为一个可编辑的程序，允许改进机制本身进化。在训练过程中，DGM-H 独立进化出持久记忆、跨代性能跟踪和多阶段评估流水线——从头构建了其自身的高级 harness。跨领域结果：

  • 论文评审：0.0 → 0.710（从空白 agent 开始）
  • 机器人奖励函数：0.060 → 0.372（超越人类基线 0.348）

Karpathy 的 Autoresearch

开源实践实现，使用 git 作为”研究记忆”——在指标改善时提交改进，在失败时回滚。Shopify 团队将其适配用于 CI 流水线优化。证明了该模式可推广到任何可度量的编码任务，而不仅仅是 ML 训练。

关键风险

  • 奖励黑客（Reward hacking）：Agent 走捷径达到指标而未实现底层目标
  • 局部最优陷阱（Local optima trap）：Agent 默认选择安全的超参数调整而非架构性突破
  • 算力燃烧（Compute burn）：无退出条件的无限改进循环
  • 安全漏洞（Security holes）：在专注于指标时产生不安全代码或绕过安全防护

投资含义

自我改进 agents 通过使 agents 更自主、减少 harness 工程中的人类瓶颈，加速了”agent 经济”的论点。构建 agent 基础设施（可观测性、评估、安全工具）的公司将受益，因为自我改进 agents 创造了对护栏和监控的需求。

经济影响

  • 软件利润率压缩：随着 UI 商品化，价值向模型层转移
  • 劳动生产率跃升：知识工作者将常规认知任务外包给 agents
  • 新的攻击面：agents 获得对凭证和支付轨道的访问权限
